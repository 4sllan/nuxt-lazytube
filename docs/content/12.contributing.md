## Contributing

Thank you for your interest in contributing to nuxt-lazytube! This guide will help you get started.

## Getting Started

### Prerequisites

- Node.js 18+ 
- pnpm (recommended) or npm/yarn
- Git
- Basic knowledge of Vue 3, Nuxt 3, and TypeScript

### Setup Development Environment

1. **Fork the repository**

   Fork the repository on GitHub and clone your fork:

   ```bash
   git clone https://github.com/YOUR_USERNAME/nuxt-lazytube.git
   cd nuxt-lazytube
   ```

2. **Install dependencies**

   ```bash
   pnpm install
   ```

3. **Run the playground**

   The playground is a Nuxt application that uses the local module:

   ```bash
   cd playground
   pnpm install
   pnpm dev
   ```

   The playground will be available at `http://localhost:3000`

4. **Run the documentation**

   The documentation is also a Nuxt application:

   ```bash
   cd docs
   pnpm install
   pnpm dev
   ```

   The documentation will be available at `http://localhost:3000`

## Development Workflow

### Running Tests

Run the test suite:

```bash
pnpm test
```

Run tests in watch mode:

```bash
pnpm test:watch
```

### Code Structure

```
nuxt-lazytube/
├── src/
│   ├── module.ts          # Main module file
│   ├── runtime/
│   │   ├── LazyYoutube.vue
│   │   ├── LazyVimeo.vue
│   │   └── utils.ts       # Utility functions
├── test/                  # Test files
├── playground/            # Development playground
├── docs/                  # Documentation site
└── package.json
```

### Making Changes

1. **Create a new branch**

   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b fix/your-bug-fix
   ```

2. **Make your changes**

   - Edit files in the `src/` directory
   - Add tests in the `test/` directory
   - Update documentation if needed

3. **Test your changes**

   ```bash
   # Run tests
   pnpm test

   # Test in playground
   cd playground
   pnpm dev
   ```

4. **Commit your changes**

   Follow the commit message convention (see below)

5. **Push and create a PR**

   ```bash
   git push origin feature/your-feature-name
   ```

   Then create a pull request on GitHub

## Commit Convention

We follow conventional commits:

- `feat:` - New feature
- `fix:` - Bug fix
- `docs:` - Documentation changes
- `style:` - Code style changes (formatting, etc.)
- `refactor:` - Code refactoring
- `test:` - Adding or updating tests
- `chore:` - Maintenance tasks

Examples:
```bash
git commit -m "feat: add support for Loom videos"
git commit -m "fix: correct thumbnail quality parsing"
git commit -m "docs: update installation guide"
```

## Pull Request Guidelines

### PR Checklist

Before submitting a PR, ensure:

- [ ] Code follows the project's style guidelines
- [ ] Tests are added/updated for new features
- [ ] Documentation is updated if needed
- [ ] All tests pass
- [ ] Commit messages follow the convention
- [ ] PR description clearly explains the changes

### PR Description

Include in your PR description:

- **What** you changed
- **Why** you changed it
- **How** to test the changes
- **Screenshots** if applicable (for UI changes)
- **Related issues** (e.g., "Fixes #123")

## Adding Features

When adding a new feature:

1. **Update the module** - Add the feature to `src/runtime/`
2. **Add tests** - Write tests in `test/`
3. **Update docs** - Document the feature in `docs/content/`
4. **Update types** - Ensure TypeScript types are correct
5. **Test manually** - Test in the playground

## Reporting Bugs

When reporting bugs:

1. **Search existing issues** - Check if the bug is already reported
2. **Create a new issue** - Use the bug report template
3. **Provide details**:
   - Nuxt version
   - nuxt-lazytube version
   - Steps to reproduce
   - Expected behavior
   - Actual behavior
   - Error messages
   - Minimal reproduction

## Suggesting Features

When suggesting features:

1. **Search existing issues** - Check if the feature is already requested
2. **Create a new issue** - Use the feature request template
3. **Provide details**:
   - What the feature should do
   - Why it's needed
   - Use cases
   - Possible implementation approach

## Documentation

### Editing Documentation

The documentation is in the `docs/` directory and uses Nuxt Content:

- Content files: `docs/content/`
- App files: `docs/app/`

To add a new documentation page:

1. Create a new `.md` file in the appropriate directory
2. Add frontmatter with title, description, and navigation icon
3. Write the content in Markdown
4. Update the navigation if needed

### Previewing Documentation

```bash
cd docs
pnpm dev
```

## Coding Standards

### TypeScript

- Use strict TypeScript
- Provide type annotations for functions
- Avoid `any` types
- Use interfaces for object shapes

### Vue Components

- Use Composition API with `<script setup>`
- Use TypeScript
- Follow Vue 3 style guide
- Use proper prop types

### Testing

- Write tests for new features
- Test edge cases
- Keep tests fast and focused
- Use descriptive test names
